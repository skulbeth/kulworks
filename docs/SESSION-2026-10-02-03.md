## 1. Clips are h264 video now, not animated WebP

**The finding.** Animated WebP has no inter-frame compression, so a clip costs
roughly (frames x pixels) and the quality setting barely moves it. Measured on the
hex press shot: q68 -> q50 only went 2.3M -> 1.9M, while dropping the width did all
the real work. Smooth motion was therefore only affordable at 6-7fps, which is what
made them stutter. Sam: *"yea, framerate is KEY to quality gifs."*

Same shot, same second:

```
animated WebP    900x600   15fps   2.3M
h264            1100x733   30fps   0.6M
```

Verified in Chrome: 90 frames shown, 0 dropped, over 3 seconds.

**What that bought, beyond quality.** A WebP must download in full before its first
frame paints; video paints `poster` instantly and streams. Nothing downloads until a
clip is on screen AND the current slide, so the carousel went from preloading three
animated WebPs (~2.4M) to one video plus three small posters. `prefers-reduced-motion`
is honoured, which an animated image cannot do: under it the page fetches **0 bytes**
of video.

**Code.** `src/components/Clip.tsx` (the player), `src/lib/clip.ts` (`isClip`,
`posterFor` — kept out of the client module so server components can call them),
wired into `Carousel.tsx`, `Placeholder.tsx`, `Lightbox.tsx`.

**Rebuild with** `bash scripts/media/build-clips.sh`. Every source path, timestamp
and crop is in there with the reasoning.

### The poster trap, which will bite again

`Clip.tsx` derives poster paths at runtime (`foo.mp4` -> `foo-poster.webp`). **No
literal reference to any `-poster.webp` exists in the source.** Every "find unused
images" sweep flags all eight as dead. They are not. Deleting them kills the first
paint on every clip. This already nearly happened once, see section 5.

## 3. Testimonials, built end to end

No Google Business account needed. **The system is live; there is no content in it.**

**Two ways in:**

- **REQUESTED** — admin > a client > "Ask for a testimonial" emails them a single-use
  link (`/testimonial/<token>`). They write it, choose the display name, tick consent.
  Asking twice re-sends the same link rather than leaving live tokens around.
- **ADDED** — admin > Testimonials > "Add one you already have": a quote, a screenshot
  of a text or email, or both.

**Consent is the gate and it is enforced twice**, at publish and again in the public
query. Verified directly: a row forced to `PUBLISHED` with `consent` false renders
nothing, and unticking it on a live one removes it immediately. Archiving is a soft
delete and is restorable.

**Security shape worth preserving:** the token is the only authentication, so the row
is created when the request is *sent* and the public endpoint only *fills it in*. A
guessed token cannot create a testimonial, and `submittedAt` makes it single-use.

**Screenshots** go to the existing private `uploads` bucket under `testimonials/`,
served by `/api/testimonial-image/[id]` rather than a signed URL, so the bucket stays
private, the URL never expires, and pending/archived screenshots are unreachable.

**Deliberately no Review/AggregateRating structured data.** Google has ignored
self-serving review markup about your own business since 2019.

Files: `src/lib/testimonials.ts`, `src/app/admin/(portal)/_testimonial-actions.ts`,
`src/app/admin/(portal)/testimonials/`, `src/app/testimonials/`,
`src/app/testimonial/[token]/`, `src/app/api/testimonial/`,
`src/app/api/testimonial-image/[id]/`, `src/components/Testimonial{Card,Form}.tsx`.

## 5. Caching, and 37 MB moved out of the deployment

**Caching.** Everything under `/images` was falling back to `max-age=0,
must-revalidate`: a conditional request per photo and clip on every visit. The bodies
came back as 304s so it was round trips rather than bytes, but on mobile that is a
dozen of them before the page settles. Now `max-age=86400,
stale-while-revalidate=2592000` in `next.config.mjs`.

**Deliberately NOT `immutable`**, because files here get overwritten in place rather
than renamed (the carousel clips were replaced several times this week) and immutable
would pin old bytes in returning browsers with no way to bust it.

**Retired media.** 64 files, 37 MB, superseded as the site was reworked. Moved to
`archive/retired-media/` with a README mapping every old URL to its new path and the
restore command. `.vercelignore` keeps `archive/` out of the deploy. Nothing deleted,
all still in git. `public/images` went 55 MB -> 18 MB.

**Two mistakes caught before they shipped**, both worth knowing:

1. The first sweep flagged all eight `-poster.webp` files as unused, because their
   paths are built at runtime. Moving them would have killed the first paint on every
   clip. The scan now resolves derived paths, not just literal strings.
2. The scratch file listing the candidates was written to the repo root, and the next
   scan read it back as a *reference*, reporting zero unused files. Any such scan must
   exclude its own output.

Verified after: all 11 public pages and all 6 portfolio galleries stepped through
image by image, **no 4xx or 5xx**.

## 7. Tile pricing raised

The $130 was **never the standard rate**: that job had the cutting die waived in
exchange for photo and video rights, which is a trade, not a price. Publishing it
under-charged every future customer who does not hand over media rights.

Now **"from about $160 delivered"** for 80 tiles at 1.5 in square, double sided.
Arithmetic: ~$100 print + ~$30 insured shipping + the $20-30 die.

Also reworded from a claim about one job into a **rate**, because once the number
moves it can no longer describe what that order was quoted.

The pricing page had no tile figure at all, just "Quote by project", so the portfolio
note was the only place a tile price appeared. It now carries the same figure plus the
reason: a tile size needs its own steel-rule die, carried on the first order and reused
on repeats, so repeat runs come in lower. **The two must move together** — noted at the
top of `src/data/pricing.ts`.

## Environment notes that cost time this session

- **`.env.local` points at the LIVE Supabase instance.** Any Prisma migration run
  locally lands on production immediately. The testimonials migration is already
  applied there. Vercel does **not** run migrations on build (`build` is just
  `next build`), so that is by design here.
- **A stale `next start` on port 3000 silently serves an old build.** It bit twice.
  The second time was worse: the old server was serving HTML while a rebuild had
  replaced its CSS chunks, so pages rendered completely unstyled. `pkill -f "next"`
  from Git Bash does **not** reliably kill it. What works:
  ```powershell
  Get-NetTCPConnection -LocalPort 3000 -State Listen |
    ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
  ```
- **Deploys:** never poll kulworks.com in a loop, it trips Vercel's Attack Challenge
  Mode. Use `npx vercel ls kulworks --yes`.
- **Turbopack** threw `next/font/google queries have exactly one entry` once, from a
  corrupted build cache. `rm -rf .next` fixed it; it was unrelated to the edit.
- **Python heredocs in Git Bash**: `\\n` inside a quoted heredoc collapsed to a real
  newline and broke a JS string literal. Build the escape with `chr()` if it matters,
  or use the Write tool.
- **Python cannot read `/d/...` bash-style paths.** Use `D:/...`.
