# Kulworks Android app + notifications: plan (started 2026-11-01 night)

Goal (Sam): get pinged on his phone when a client opens, approves, pays or contacts, without
relying on texting. Carrier email-to-SMS gateways (`NOTIFY_SMS`) have been shut down by the
big US carriers, which is why the lead texts stopped. Android first.

## Decisions

- **The app is the existing admin**, wrapped as an installable Android app (Trusted Web
  Activity, built with Bubblewrap). One codebase: every admin feature ships to the app the
  moment it deploys, with no app-store release per change. No Firebase project, no Play account.
  The APK is sideloaded; it can go on the Play Store later from the same project.
- **Notifications = Web Push (VAPID)** from our own server via the `web-push` package. In a TWA,
  Chrome delegates them to the app, so they show under the Kulworks app icon.
- **Every notification is also a row in a `Notification` table** so the app has an inbox
  (bell + unread count). Push is the doorbell; the inbox is the record. A push that fails
  is never lost.
- **One entry point: `notify()`** in `src/lib/notify.ts`. Never throws (a broken push can't
  break a client's accept/approve), prunes dead devices (404/410), and respects per-kind
  on/off settings.
- **Payments are never auto-marked paid.** A detected receipt raises "Looks like Erin paid
  $109 (Zelle)" with a one-tap **Mark paid** in the app. Money stays a human decision.

## Events (kind → when)

| kind | trigger |
|---|---|
| `lead` | new quote-form submission (/api/quote), order form (/api/order) |
| `doc_viewed` | client's FIRST open of a quote/invoice, and "opened again" after 24h+ quiet |
| `proof_viewed` | first open of a proof page |
| `quote_accepted` | "Looks good, let's do it" |
| `quote_extend` | expired quote: "ask about extending" |
| `address` | client saved shipping details |
| `proof_notes` | client pressed "Send my notes" |
| `proof_approved` | client pressed "Approve all" |
| `upload` | client uploaded files (/api/upload) |
| `testimonial` | testimonial submitted |
| `message` | client message from the quote/proof page (new: "Message Sam" box) |
| `email_reply` | a known client emailed (Gmail sweep) |
| `payment` | a payment receipt email matched an unpaid invoice (Gmail sweep) |

## Phases

1. **Hub**: Prisma `PushDevice` + `Notification`, `lib/notify.ts`, VAPID keys in Vercel env.
2. **Triggers** wired into every route/action above.
3. **Admin UI**: `/admin/notifications` inbox, bell with unread badge in the admin nav,
   "Turn on notifications on this device", "Send a test", per-kind switches.
4. **PWA**: `manifest.webmanifest` (scope /admin/), icons (192/512/maskable), `sw.js`
   (push, notificationclick to the right page, no fetch caching, so the public site is untouched).
5. **Android**: portable JDK 17 + Android SDK in `C:\skulbeth\_toolchains`, Bubblewrap
   project in `C:\skulbeth\Kulworks-android`, signed APK, `/.well-known/assetlinks.json`
   so the app runs full-screen (no URL bar).
6. **Gmail sweeps**: client replies + payment receipts. Vercel Hobby only allows daily
   crons, so the sweep runs lazily (at most every 10 min, kicked by site traffic and by
   opening the app) plus the daily cron.
7. **Client "Message Sam" box** on quote + proof pages (contact that isn't email).
8. Test (harness + real browser push), deploy, docs, handoff.

## Testing

- Server: the action harness (loader maps @/ to src; stubs auth/cache/nav/email) on a
  throwaway client; every test row deleted after.
- Push: a real Chrome profile subscribes on localhost, the server sends, the service worker's
  receipt is checked.
- Android: build the APK, check the manifest/signature with aapt/apksigner. Installing it on
  the phone is Sam's step (no device connected).

## Needs Sam (collected in HANDOFF)

- Install the APK, log in, tap "Turn on notifications".
- Payments: a Gmail filter in his personal account forwarding Venmo/Zelle/PayPal receipts to
  kulworksdesign@gmail.com (they don't reach the Kulworks inbox today).
- Optional: Play Store listing; Mailgun inbound webhook (instant email alerts).
