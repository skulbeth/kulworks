## 1. The form asks up front

New optional columns on `Submission` (migration
`20261020120000_submission_due_delivery`, additive, applied to the live DB with
`npm run db:deploy`): `dueDate`, `deliveryMethod` (`pickup` | `ship` | `meetup`),
`shipStreet`, `shipCity`, `shipState`, `shipPostalCode`, `cardBacks` (`same` |
`different`).

- **Labels and rules live in one place:** `src/lib/order-details.ts` (delivery and
  card-back options, `RUSH_FEE`, `isRush`, the fees note, the address formatter). The
  form, calculator, API, admin and emails all import from it.
- **Quote form** (`ContactForm.tsx`): due date (date picker, optional, can't pick a
  past day), delivery (required radio), the address block appears when Shipped is
  picked (all four lines required), and the card-backs question appears only when a
  card type is ticked (card printing, card design, prototype). Picking "different back
  per card" shows the note to label each back clearly. A date under 3 days out shows
  "a $15 rush fee applies" right under the picker.
- **API** (`/api/quote`): validates everything. Junk values are dropped to null rather
  than rejected, except "Shipped" without the full address, which is a 400. The due date
  is stored at noon UTC so it is the same calendar day in every timezone.
- **Admin:** the submission shows Needed by (with a "Rush at request time" tag),
  Delivery (with the address and a Copy button) and Card backs. Converting to a project
  copies `dueDate` and the `ship*` fields onto the Project (they already existed there),
  puts delivery method and card backs in the project notes, and pushes the due date to
  the Kulworks calendar with its auto-reminder, same as an edit would.
- **Emails:** the new-request email to Sam and the customer's confirmation both list the
  due date (flagged RUSH when under 3 days), delivery, address and card backs.

## 2. Fees shown up front

- `RUSH_FEE = 15`, `RUSH_WITHIN_DAYS = 3`. Rush means the due date is today, tomorrow or
  the day after (a past date counts too).
- **Calculator:** new "Needed in hand by" date. Under 3 days adds a "Rush fee" row
  inside the production subtotal, so the 9% service charge applies to it exactly as it
  does when the rush fee is an invoice line (`computeTotals` charges on the whole
  subtotal). The calculator's 9% now reads `site.payments.defaultServiceCharge`, the
  same setting invoices default to, so they can't drift. The handoff passes `&due=` so
  the form arrives with the date filled in.
- **Notes:** "Shipping is added to your invoice, and a travel fee may apply for meetups
  far across or outside San Antonio" is on the form, the calculator and /pricing/ (which
  also gained "Rush (production in under 3 days): $15 flat").
- Not built: the "% of order with a $15 minimum" idea from the TODO. Flat $15 only.

## 4. Why Janice's Drive folder never appeared

Nothing failed, and the error log was empty around her submission for that reason.
Commit `fca20c4` (2026-07-25, Sam's call at the time) stopped the website from creating
folders: the checkbox only set `driveFolder`, and folders were made from the admin's
"Create shared folder" button. Sam now expects the checkbox to make the folder, so
`/api/quote` creates it again (same "C - Name - date" naming as the admin button), saves
the link, and puts it in the customer's confirmation email (one email, not the separate
"your folder" email the July code removed). The admin button stays for requests that
didn't tick the box.

Second gap found on the way: `createClientFolder` only `console.error`s and returns null
when Drive refuses, so a real failure was invisible. The route now writes it to the
ErrorLog ("/api/quote drive folder"), and also logs when a folder was requested but
Drive isn't configured.

`scripts/e2e-smoke.mjs` has asserted "Drive folder auto-created" all along, so it would
have failed from July until now.
